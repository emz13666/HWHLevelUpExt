# HWHLevelUpExt

[![Version](https://img.shields.io/badge/version-1.20-blue.svg)](https://github.com/emz13666/HWHLevelUpExt)
[![License](https://img.shields.io/badge/license-MIT-green.svg)](LICENSE)
[![HeroWarsHelper](https://img.shields.io/badge/requires-HeroWarsHelper%20v2.474%2B-orange.svg)](https://greasyfork.org/ru/scripts/450693-herowarshelper)

Расширение для юзерскрипта **[HeroWarsHelper](https://greasyfork.org/ru/scripts/450693-herowarshelper)** (автор ZingerY), добавляющее кнопку **«Повысить уровень»** в меню **«Разное»**.

Скрипт повышает уровень выбранных героев до уровня аккаунта, точно рассчитывая количество зелий опыта и не допуская перерасхода.

---

## ✨ Возможности

- 🎯 **Точный расчёт опыта** — используется проверенное суммарное значение XP для 130-го уровня (`3 625 195`) и `lib.getData('level')` для промежуточных уровней.
- 📦 **Отправка пачками** — до 200 зелий за один запрос, чтобы не упираться в лимиты сервера при больших объёмах.
- 🛡️ **Безопасная обработка `maximum xp`** — если сервер применил меньше зелий, чем в пачке (герой достиг максимума в середине), остаток корректно отбрасывается без ошибки.
- 🔁 **Страховка от рассинхрона** — если после точного расчёта герой всё ещё ниже цели, скрипт «добивает» недостающее пачками, перечитывая данные героя после каждого шага.
- 🚪 **Ранний выход** — если зелья закончились, обработка оставшихся героев немедленно прерывается.
- 👀 **Список всегда доступен** — форму выбора героев можно открыть даже при отсутствии зелий (например, чтобы посмотреть, кого можно повышать).
- 💾 **Сохранение выбора** — отмеченные герои и режим «Все имеющиеся герои» запоминаются между сессиями.
- 🌐 **Локализация** — русский и английский (fallback).

## 🚀 Использование

1. Откройте игру **Hero Wars** и дождитесь полной загрузки.
2. На панели HeroWarsHelper нажмите **«Разное»**.
3. Выберите **«Повысить уровень»**.
4. В открывшемся окне:
   - Отметьте героев, которых нужно повысить, **или** включите чекбокс **«Все имеющиеся герои»**.
   - Нажмите **«Выполнить»**.
5. Наблюдайте прогресс в верхней строке статуса. По завершении появится сводка с количеством использованных зелий и остатком по каждому типу.

> ⚠️ **Интерфейс игры не обновляет уровни героев сразу.** Полноценное отображение произойдёт после перезагрузки страницы игры. При повторном открытии формы данные героев перечитываются с сервера, поэтому в списке будут актуальные уровни.

## ⚙️ Как это работает

### Расчёт опыта

Для 130-го уровня используется константа:

```javascript
const MAX_HERO_XP = 3625195;
```

Значение проверено по данным самого HeroWarsHelper — у всех героев 130-го уровня `xp === 3625195`.

Для промежуточных уровней (`userLevel < 130`) скрипт пытается получить суммарный опыт из библиотеки игры:

```javascript
const exp = lib.getData('level')?.hero?.[userLevel]?.exp;
```

Значение принимается только при выполнении всех условий:

- число, конечное;
- `> 0`;
- `> currentXp` (иначе это не суммарный, а per-level опыт);
- `< 100 000 000`.

Если хоть одно условие не выполнено — скрипт переключается в **режим пачками** (см. ниже).

### Режимы работы

| Режим | Когда используется | Как работает |
|---|---|---|
| **Точный** | `targetXp` известен (всегда для 130-го, обычно для промежуточных) | Вычисляется `neededXp = targetXp - currentXp`, зелья подбираются от малых (9 → 10 → 11 → 12) так, чтобы точно покрыть остаток |
| **Пачками** | `targetXp` неизвестен (для промежуточных уровней с невалидным `lib.exp`) **или** как страховка после точного расчёта | Отправляет по 200 зелий за итерацию, перечитывая данные героя, пока цель не достигнута или зелья не кончатся |

### Порядок использования зелий

```
9 (малые, 500 XP) → 10 (средние, 1500 XP) → 11 (большие, 5000 XP) → 12 (огромные, 15000 XP)
```

Сначала мелкие — так проще точно «добить» остаток без перерасхода.

### Обработка ошибки `maximum xp`

Если сервер вернул:

```
NotAvailable in consumableUseHeroXp: Unit already has maximum xp
```

Это означает, что в пачке было больше зелий, чем нужно герою для достижения максимума. Сервер применил столько, сколько нужно, а на остаток вернул ошибку. Скрипт:

1. Логирует это как **нормальное событие**, а не критическую ошибку;
2. **Не списывает** неприменённый остаток из локального счётчика;
3. Переходит к следующему герою.

## 🔧 Настройки

Все константы вынесены в начало скрипта:

```javascript
// Порядок и XP зелий
const XP_POTION_IDS = [9, 10, 11, 12];
const potionXp = { 9: 500, 10: 1500, 11: 5000, 12: 15000 };

// Параметры прокачки
const MAX_HERO_LEVEL = 130;
const MAX_HERO_XP = 3625195;            // суммарный XP для 130-го уровня
const MAX_PER_REQUEST = 200;            // зелий за один запрос
const MAX_FALLBACK_ITERATIONS = 2000;   // защита от зависания
```

Если сервер начнёт отвечать ошибкой именно на размер `amount: 200` (не на `maximum xp`) — уменьшите `MAX_PER_REQUEST` до `100` или `50`.

## 🐛 Известные особенности

- **UI не обновляется после прокачки.** Связано с тем, как игра кэширует данные героев. Уровни обновятся после перезагрузки страницы. Это поведение осознанное — скрипт **не вызывает** `cheats.refreshGame()` в конце, так как он всё равно не помогает.
- **Список показывается даже без зелий.** Если пользователь запустил прокачку без зелий, скрипт единожды покажет `Нет зелий опыта` и выйдет — не пытаясь пройти по всем героям.
- **Промежуточные уровни.** Для `userLevel < 130` точность может быть ниже, если библиотека игры отдаёт `lib.getData('level').hero[level].exp` в формате «опыт за уровень». В этом случае включается режим пачками.
